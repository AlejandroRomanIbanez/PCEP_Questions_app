==QUESTION 1==
In OOP, what is inheritance?
[A] The ability for a class to contain objects of another class.
[B] The mechanism of basing a new class (subclass) on an existing class (superclass), inheriting its attributes and methods.
[C] The ability of a method to behave differently based on the object it is called on.
[D] The bundling of data and methods into a single unit.

CORRECT: B
EXPLANATION: Inheritance is a core OOP principle that allows for code reuse and the creation of a hierarchy of classes, where subclasses can specialize the behavior of their superclasses.

==QUESTION 2==
What is the primary purpose of the `super()` function in Python?
[A] To call a method in the base class from a method in the derived class.
[B] To check if a class is a superclass of another.
[C] To create an instance of the superclass.
[D] To define a method that cannot be overridden.

CORRECT: A
EXPLANATION: `super()` provides a way to access methods of a parent class, which is particularly useful for extending, rather than completely replacing, the functionality of an inherited method (like `__init__`).

==QUESTION 3==
What is polymorphism in the context of Python?
[A] The ability of different classes to be treated as instances of a common superclass.
[B] The ability for different objects to respond to the same method call in a way specific to their class.
[C] Having multiple methods with the same name but different parameters within a single class.
[D] The process of inheriting from multiple base classes.

CORRECT: B
EXPLANATION: Polymorphism allows objects of different classes to be handled via a uniform interface. For example, a `draw()` method can be called on various shape objects (`Circle`, `Square`), and each will execute its own specific version of `draw()`.

==QUESTION 4==
Consider the following code:
```python
class A:
    def greet(self):
        print("Hello from A")
class B(A):
    def greet(self):
        print("Hello from B")
        super().greet()
b = B()
b.greet()
```
What is the output?
[A] Hello from A
[B] Hello from B
[C] Hello from B followed by Hello from A
[D] Hello from A followed by Hello from B

CORRECT: C
EXPLANATION: The `greet` method in class `B` is called first, printing "Hello from B". The `super().greet()` line then explicitly calls the `greet` method from the parent class `A`, which prints "Hello from A".

==QUESTION 5==
What is Method Resolution Order (MRO) in Python?
[A] The order in which methods are defined within a class.
[B] The rule that determines the order in which base classes are searched when looking for a method.
[C] The specific order for calling `super()` in the `__init__` method.
[D] The priority of instance methods over class methods.

CORRECT: B
EXPLANATION: MRO defines the sequence in which parent classes are traversed when searching for a method. Python uses the C3 linearization algorithm to determine this order, which is crucial in multiple inheritance scenarios.

==QUESTION 6==
What is the main difference between `isinstance(obj, Class)` and `type(obj) is Class`?
[A] There is no difference; they are functionally identical.
[B] `isinstance()` returns `True` if `obj` is an instance of `Class` or any of its subclasses, while `type()` only checks for an exact match.
[C] `type()` is faster than `isinstance()`.
[D] `isinstance()` can only be used with built-in types.

CORRECT: B
EXPLANATION: `isinstance()` is polymorphic. It respects the class hierarchy. `type()` is not polymorphic; it returns the exact class of an object, making it less flexible for checking object types in an inheritance hierarchy.

==QUESTION 7==

[A] `True`
[B] `False`

==QUESTION 9==
What is "duck typing"?
[A] A type system where an object's suitability is determined by the presence of certain methods and attributes, rather than its explicit type.
[B] A strict type system where inheritance must be explicitly declared.
[C] A feature that allows methods to be renamed at runtime.
[D] A way to create private methods in a class.

CORRECT: A
EXPLANATION: Duck typing follows the principle: "If it walks like a duck and it quacks like a duck, then it must be a duck." In Python, this means you can use any object in a particular context as long as it has the required methods, regardless of its class.

==QUESTION 10==

[B] There is no built-in, enforced way to do this in Python.
[C] Prefix the method name with a double underscore.
[D] Use the `private` keyword.

EXPLANATION: Unlike languages like Java or C#, Python does not have a `final` keyword to prevent method overriding. While name mangling (`__`) makes overriding harder, it doesn't prevent it. The convention is to rely on documentation.

==QUESTION 12==
What is the "diamond problem" in multiple inheritance?
[A] A problem where a class has exactly four parent classes.
[B] An ambiguity that arises when a class inherits from two superclasses that both inherit from the same grandparent class, which can lead to confusion about which version of a method to inherit.
[C] A performance issue caused by deep inheritance chains.

CORRECT: B
EXPLANATION: The diamond problem occurs when a method in the grandparent class is overridden by the two parent classes. Python's MRO is designed to resolve this ambiguity in a predictable way.

==QUESTION 15==
What is the output of the following code?
```python

    def make_sound(self):
        raise NotImplementedError

class Cat(Animal):
    def make_sound(self):
        return "Meow"

class Dog(Animal):
    def make_sound(self):
        return "Woof"

animals = [Cat(), Dog()]
for animal in animals:
    print(animal.make_sound())
```
[A] It raises a `NotImplementedError`.
[B] Meow followed by Woof.
[C] It raises a `TypeError`.
[D] Nothing is printed.

CORRECT: B
EXPLANATION: This is an example of polymorphism. Both `Cat` and `Dog` are treated as `Animal` types, but when `make_sound()` is called, Python executes the specific version of the method defined in each subclass.

==QUESTION 23==
What is the output?
```python
class X: v = 1
class Y(X): v = 2
class Z(Y): pass
z = Z()
print(z.v)
```
[A] `1`
[B] `2`
[C] `None`
[D] `AttributeError`

CORRECT: B
EXPLANATION: When `z.v` is accessed, Python follows the MRO. It first checks class `Z`. Not finding `v`, it checks `Z`'s parent, `Y`. It finds `v` in `Y` with a value of 2 and stops searching.
