==QUESTION 1==
What is a key characteristic of a Python generator?
[A] It stores all its values in memory at once.
[B] It uses the `yield` keyword to produce a series of values lazily, one at a time.
[C] It can only be iterated over once.
[D] It is a special type of list that cannot be modified.

CORRECT: B
EXPLANATION: Generators are memory-efficient because they produce items on demand. The `yield` statement pauses the function's execution and saves its state, resuming from where it left off on the next iteration.

==QUESTION 2==
What is the primary difference between an iterator and an iterable?
[A] An iterable can be looped over, while an iterator is the object that performs the actual iteration.
[B] An iterator can be looped over, while an iterable cannot.
[C] They are the same thing.
[D] An iterable has a `__next__` method, and an iterator has an `__iter__` method.

CORRECT: A
EXPLANATION: An iterable is any object that can return an iterator (i.e., it has an `__iter__` method, like a list). An iterator is an object with a `__next__` method that keeps track of the state and produces the next value in a sequence.

==QUESTION 3==
Which methods must a class implement to be considered an iterator?
[A] `__init__` and `__next__`
[B] `__iter__` and `__next__`
[C] `__iter__` and `__len__`
[D] `__start__` and `__stop__`

CORRECT: B
EXPLANATION: To conform to the iterator protocol, an object must have an `__iter__` method (which should return `self`) and a `__next__` method to return the subsequent item.

==QUESTION 4==
What is a closure in Python?
[A] The process of closing a file automatically.
[B] A class that has no methods.
[C] A function object that remembers values in the enclosing lexical scope even when they are not present in memory.
[D] A way to make class attributes private.

CORRECT: C
EXPLANATION: A closure is created when a nested function references a value from its containing function's scope. The inner function "closes over" that variable, retaining access to it even after the outer function has finished executing.

==QUESTION 5==
What will be printed when the following code is executed?
```python
def my_generator():
    yield 1
    yield 2

g = my_generator()
print(next(g))
print(next(g))
```
[A] 1 followed by 2
[B] 1 followed by 1
[C] 2 followed by 1
[D] It will print the generator object itself twice.

CORRECT: A
EXPLANATION: Calling `my_generator()` creates a generator object. The first `next(g)` executes the function until the first `yield`, producing `1`. The second `next(g)` resumes execution and runs until the next `yield`, producing `2`.

==QUESTION 6==
What happens when a generator function completes or a `return` statement is executed?
[A] It raises a `StopIteration` exception on the next `next()` call.
[B] It starts over from the beginning.
[C] It raises a `ValueError`.
[D] It returns `None` indefinitely.

CORRECT: A
EXPLANATION: The `StopIteration` exception is the standard way for an iterator to signal that it has no more values to produce. `for` loops automatically catch this exception to terminate.

==QUESTION 7==
Consider the following closure:
```python
def outer(x):
    def inner(y):
        return x + y
    return inner

add_five = outer(5)
print(add_five(10))
```
[A] 5
[B] 10
[C] 15
[D] It raises a `NameError`.

CORRECT: C
EXPLANATION: The `outer(5)` call creates a closure where `x` is bound to `5`. The returned `inner` function (now named `add_five`) remembers this value. When `add_five(10)` is called, it calculates `5 + 10`.

```python

for value in g:
    print(value, end=' ')
for value in g:
    print(value, end=' ')
```
[A] `0 2 4 0 2 4`
[B] `0 2 4`
[C] `0 2 4` followed by a `StopIteration` error.

CORRECT: B
EXPLANATION: Generators can only be exhausted once. The first `for` loop iterates through the generator and consumes all its values. The second `for` loop has nothing to iterate over, so it terminates immediately without printing anything.

==QUESTION 16==
What is the value of `c` after this code executes?
```python
def counter(start):
    count = start
    def increment():
        nonlocal count
        count += 1
        return count
    return increment
c = counter(5)
c()
c()
```
[A] `5`
[B] `6`
[C] `7`
[D] It raises an error.

CORRECT: C
EXPLANATION: This is a closure where `increment` has access to the `count` variable from its enclosing scope. The `nonlocal` keyword is crucial for allowing `increment` to modify `count`. The last call to `c()` returns 7.
