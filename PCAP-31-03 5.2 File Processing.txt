==QUESTION 1==
What is the main advantage of using the `with open(...) as f:` statement for file handling?
[A] It opens files in a more secure mode.
[B] It automatically closes the file, even if errors occur inside the block.
[C] It reads the entire file into memory at once.
[D] It is the only way to write to a file.

CORRECT: B
EXPLANATION: The `with` statement creates a context manager. For files, this ensures that the file's `close()` method is automatically called upon exiting the block, which prevents resource leaks.

==QUESTION 2==
Which mode is used to open a file for writing, but only if the file does not already exist?
[A] `'w'` (write mode)
[B] `'a'` (append mode)
[C] `'x'` (exclusive creation mode)
[D] `'w+'` (write and read mode)

CORRECT: C
EXPLANATION: The `'x'` mode is for exclusive creation. It will create and open a file for writing, but if the file already exists, it will raise a `FileExistsError`.

==QUESTION 3==
What does the `f.read()` method return if called without an argument?
[A] The first line of the file.
[B] A list of all lines in the file.
[C] A single string containing the entire content of the file from the current position.
[D] It raises a `ValueError`.

CORRECT: C
EXPLANATION: `f.read()` reads from the current file cursor position until the end of the file and returns the content as a single string.

==QUESTION 4==
After executing `f.write("hello")`, what does the `f.tell()` method return, assuming the file was opened in `'w'` mode and was initially empty?
[A] `0`
[B] `4`
[C] `5`
[D] `None`

CORRECT: C
EXPLANATION: The file cursor moves to the position after the last written byte. Since "hello" has 5 characters (and thus 5 bytes in standard encoding), `tell()` will return 5.

==QUESTION 5==
What is the difference between `'w'` mode and `'a'` mode for opening files?
[A] `'w'` can only write strings, while `'a'` can write bytes.
[B] `'w'` creates the file if it doesn't exist, while `'a'` raises an error.
[C] `'w'` overwrites the existing file content, while `'a'` appends new content to the end of the file.
[D] There is no difference.

CORRECT: C
EXPLANATION: `'w'` (write) mode will truncate the file if it exists, deleting all previous content. `'a'` (append) mode will place the file cursor at the very end of the file, preserving existing content.

==QUESTION 6==
What does the `f.readlines()` method return?
[A] A single string with newline characters.
[B] An iterator that yields lines one by one.
[C] A list of strings, where each string is a line from the file including the newline character.
[D] The number of lines in the file.

CORRECT: C
EXPLANATION: `readlines()` reads the entire file and splits it by lines, returning a list. This can consume a lot of memory for large files.

==QUESTION 7==
How do you open a file for both reading and writing?
[A] `'rw'`
[B] `'r+'` or `'w+'`
[C] `'wr'`
[D] You must open it twice, once for reading and once for writing.

CORRECT: B
EXPLANATION: The `+` sign adds the opposite capability. `'r+'` opens for reading and writing (file must exist). `'w+'` opens for writing and reading (truncates the file if it exists).

==QUESTION 8==
What is the most memory-efficient way to process a large text file line by line?
[A] `for line in open('large.txt'): process(line)`
[B] `lines = open('large.txt').readlines(); for line in lines: process(line)`
[C] `content = open('large.txt').read(); lines = content.split('\n'); for line in lines: process(line)`
[D] All are equally efficient.

CORRECT: A
EXPLANATION: Iterating directly over the file object (`for line in f:`) is the most efficient method because it reads the file line by line without loading the entire file into memory.

==QUESTION 9==

[C] To create a symbolic link between two paths.
[D] To check if two paths point to the same file.

==QUESTION 14==
What is the difference between text mode (`'t'`) and binary mode (`'b'`) when opening a file?
[A] Text mode is for reading, binary mode is for writing.
[B] In text mode, Python performs encoding/decoding of strings, while in binary mode, it reads/writes raw bytes.
[C] Binary mode is faster than text mode.

==QUESTION 15==

```python
    f.write('123')
with open('data.txt', 'a') as f:
    f.write('456')
```
[A] `456`
[B] `123`

==QUESTION 19==
What is buffered I/O?
[A] A method of reading files backwards.
[B] Reading/writing data in chunks (a buffer) to improve performance, rather than one byte at a time.
[C] A way to open multiple files at once.
[D] Encrypting file content as it is written.

==QUESTION 23==
What will be the content of `data.txt` after this code runs?
```python
with open('data.txt', 'w') as f:
    f.write('Line 1\n')
    f.seek(0)
    f.write('Line 2')
```
[A] `Line 1\nLine 2`
[B] `Line 2\n`
[C] `Line 2ine 1\n`
[D] `Line 2`

CORRECT: B
EXPLANATION: `f.write('Line 1\n')` writes 7 bytes and moves the cursor to position 7. `f.seek(0)` moves the cursor back to the beginning. `f.write('Line 2')` then writes 6 bytes, overwriting the first 6 bytes of the original content. The file now contains `Line 2\n`.

==QUESTION 28==
What is the content of the file after running this code?
```python
with open('file.txt', 'w+') as f:
    f.write('abc')
    f.seek(0)
    content = f.read()
    f.write('def')
```
[A] `abcdef`
[B] `def`
[C] `defabc`
[D] `abc`

CORRECT: A
EXPLANATION: `'w+'` truncates the file. `f.write('abc')` writes 'abc' (cursor is at position 3). `f.seek(0)` moves cursor to the start. `f.read()` reads 'abc' (cursor is back at position 3). `f.write('def')` writes 'def' at the current position 3. The final content is 'abcdef'.
